# DispatchFlow 前端视觉重构任务路线图

> 制定日期：2026-08-24
> 范围：管理端 Web、地图监控页、移动端履约页
> 使用方式：按阶段执行；完成实现与验收后，将对应 `- [ ]` 更新为 `- [x]`。未通过验收不得勾选。
> 变更边界：不改路由、接口、权限、业务流程、埋点名称或地图业务规则；仅重构视觉层级、布局与交互反馈。

## 0. 设计基线与边界

- [x] 落实 **Operational Clarity（运营清晰度）**：以信息优先级、留白和内容对齐组织高密度业务界面。
- [x] 将青色限制为当前选中、可执行操作和实时连接；红、黄、绿仅表达风险、提醒和正常状态。
- [x] 取消普通内容的默认卡片化；仅独立阅读、可拖动或覆盖背景的内容使用容器。
- [x] 保留低反光、低噪声的深色工作环境，移除网格背景、光晕和泛用渐变。
- [x] 采用设计控制参数：`DESIGN_VARIANCE 3 / MOTION_INTENSITY 2 / VISUAL_DENSITY 8`。

**本阶段落地说明（2026-08-24）**

- 以 `front/src/config/visualPolicy.ts` 固化视觉用途、禁止项和受保护业务边界，并在根节点暴露只读诊断标记。
- 以 `front/src/styles/tokens.css` 与 `front/src/config/tokens.ts` 同步三层表面、交互色、状态色、圆角、阴影和动效预算。
- 以 `front/src/styles/global.less` 与 `front/src/config/theme.ts` 取消全局径向光、主按钮发光、普通卡片阴影和 hover 上移；业务页面结构留待后续阶段。
- 通过 `npm run check:visual-baseline` 守卫基础视觉层；局部页面中的历史硬编码视觉债务仍按第 1～3 节逐项治理。
