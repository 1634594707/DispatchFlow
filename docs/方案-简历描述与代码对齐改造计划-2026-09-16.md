## 1. 结论与边界

1. 本项目不是从零开始。已承载且有代码背书的能力（2026-09-16 逐条核实）：加权 Dijkstra 路网寻路（`ParkRoutePlannerServiceImpl.shortestNodePath`）、Haversine 米制边权（`ParkRoadGraph.edgeCost`）、MAPF 时空预约+冲突重规划（`MapfRoutePlannerService`，默认启用）、多目标加权选车（`DispatchVehicleAssignServiceImpl.scoreCandidate`）、全链路 SOC 校验、分级补能阈值（`FleetEnergyProperties`：20/5/90/30）、Outbox+三队列、VDA5050、grayPercent 灰度。这些是底座，不是重写对象。
2. 本次只做**一个 MVP：预测链路落地**（P2 工作包）。理由：它是简历上唯一"整条虚构"的能力，也是唯一需要新写训练代码的项；其余两项（A*、压测）是已有代码的小增量。
3. 平行线（不作为主线）：CARLA/OpenDRAMA 真实仿真（`scripts/carla/`）保持隔离试验线，本次不接入预测链路。
4. 不在本阶段做：路网多源绑定重构（P0 遗留项，另行立项）、前端预测大屏（只做接口与最小展示）、CBS/PBS 级 MAPF 算法升级、真实车队接入变更。

## 3. 产品与架构定阵

### 3.1 唯一主场景用户旅程
> 用户输入 / 触发："返充时机与站点容量判断需要量化输入，而不是拍阈值"

1. **需求确认**：预测输出定义为——各站点未来时段补能需求区间（P50/P90）+ 站点到站压力（滑窗 P95），供返充决策与容量告警消费
2. **数据准备**：从 `charging_session` + 订单/到站记录抽取站点×时段历史序列（SQL 导出 CSV）
3. **训练与评估**：Python 脚本特征工程 → XGBoost 分位数回归 → 输出 pinball loss + P90 覆盖率评估报告
4. **接入**：预测结果落表 / JSON，Java 侧 `EnergyForecastService` 读取，接入返充时机提示与站点容量判断（先提示后干预，不直接改派单决策）
5. **发布**：合并主干，压测与评估数字写入简历对应条目
6. **度量**：P90 覆盖率、pinball loss、预测任务耗时、Java 消费延迟

### 3.2 首批节点（只做 4 个）
| 节点 | 输入 | 输出 | 失败处理 | 现有能力复用 |
| --- | --- | --- | --- | --- |
| `feature_extract` | charging_session / 订单记录（SQL） | 站点×时段特征 CSV | 无历史数据时用仿真回放生成，并明确标记"仿真数据" | MySQL 既有表 |
| `train_forecast` | 特征 CSV | 模型文件 + P50/P90 预测 JSON + 评估报告（coverage/pinball） | 样本不足降级为滑窗统计基线，XGBoost 对比基线报告提升幅度 | scripts/ Python 惯例 |
| `forecast_consume` | 预测 JSON / 表 | `EnergyForecastService` 查询接口 + 返充提示字段 | 预测缺失时回退现有纯阈值策略 | FleetChargePolicy / Redis 热更新 |
| `scale_bench` | 仿真配置（100车/500单/1000节点） | JUnit 压测报告（派单 P95、完成率） | 超时/异常自动降规模重跑 | MapfLoadTest 的网格图构造模式 |

**节点通用契约：** 输入数据版本、输出版本、随机种子固定（可复现）、预测时间窗与站点 ID 绑定、评估指标随输出落盘。

### 3.3 组件归属
- **保留在现有系统：** 派单、补能策略、状态机、Outbox——预测只读不写，不侵入派单决策
- **新建为独立模块：** `scripts/ml/`（训练脚本）、`fsd-dispatch` 内 `EnergyForecastService` + `energy_forecast_result` 表、`DispatchScaleLoadTest`
- **不可直接共享数据库写入：** 预测模块只新增自己的结果表，禁止写订单/充电/车辆表；消费侧通过 service 接口读取

## 8. 试点指标与止损线
| 指标 | 目标 | 止损 / 处理线 |
| --- | --- | --- |
| A* 最优性测试 | 路径长度与 Dijkstra 一致 | 不一致：检查 h 是否 admissible，未修复不合并 |
| P90 覆盖率（仿真数据） | ≥ 80% | < 60%：特征不足，降级滑窗统计基线并在简历如实写基线方法 |

| 既有测试回归 | 0 失败 | 任一失败：冻结新功能先修 |
| 预测任务可复现性 | 固定种子两次运行结果一致 | 不可复现：修随机性后再训练 |
